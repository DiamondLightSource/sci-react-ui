# Cognitive accessibility and usability

People differ in how they process information, maintain focus, and recover from
errors. In scientific software, users may work for long periods or run live
experiments where mistakes are costly. The goal is not to simplify the science,
but to remove cognitive load the interface adds.

## Design objectives

<ul>
  <li>
    <strong>Be understandable</strong>: use familiar patterns and terminology,
    and make state visible at a glance.
  </li>
  <li>
    <strong>Reduce memory burden</strong>: keep important information visible
    and favour recognition over recall.
  </li>
  <li>
    <strong>Support focus</strong>: avoid competing emphasis and keep
    navigation consistent.
  </li>
  <li>
    <strong>Prevent and recover from errors</strong>: show consequences before
    actions, and make recovery obvious and forgiving.
  </li>
  <li>
    <strong>Design for long sessions</strong>: assume users are tired,
    interrupted, or multitasking.
  </li>
</ul>

## Quick sense check

<ul>
  <li>Is it understandable without prior knowledge?</li>
  <li>Does it rely on memory or hidden behaviour?</li>
  <li>Is important state clearly visible?</li>
  <li>Is error recovery clear and forgiving?</li>
  <li>Would it still be clear at the end of a long experiment session?</li>
</ul>
